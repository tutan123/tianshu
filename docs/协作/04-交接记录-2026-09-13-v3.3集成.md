## 1. 我发现的核心问题：v3.3 是一个半集成分支

GPT-6 的 SDD 计划（`docs/superpowers/plans/2026-09-13-interiors-rpg.md`）有 4 个 Task，Task 1–3 写了代码，**Task 4「Acceptance and Delivery」完全没做**。后果是：

### 1.1 三个新文件根本没被加载

`index.html` 里没有 `characters.js`、`interiors.js`、`character-ui.css`。

- `characters.js`（13 位具名角色的工厂）→ 死代码
- `interiors.js`（八套独立室内平面）→ 死代码
- `character-ui.css` → RPG 四视图完全没有样式

### 1.2 `exploration.js` 改了坐标，几何却没换

`exploration.js` 已经改成从 `Interiors.positions(zone)` 取坐标（新布局），但 `campus3d.js` 仍然调用 `WorldArt.interior(id)`（旧的八区共用四房间平面）。

**结果：新坐标落在旧墙体里。** 实测 `dorm-stamp (14,-11)`、`dorm-student (0,-4)`、`dorm-note (-13,-10)` 三个点 `clearAt` 为 `false`，玩家走不过去。

### 1.3 更深的根因：`WorldArt.interactables` 没有导出

`interiors.js:146` 调用 `WorldArt.interactables(root, objects)`，但 `world-art.js` 的返回对象里**没有这个函数**（它是私有函数）。

```
TypeError: WorldArt.interactables is not a function
    at Object.build (interiors.js:146)
```

`Interiors.build()` 每次都抛异常 → `campus3d` 的 try/catch 静默回落到旧布局 → 表面上"能进室内"，实际上新室内永远显示不出来。**这个失败是静默的**，只在 UI 上弹一个 toast，控制台和 `pageerror` 都抓不到。这就是为什么单元测试和之前的验收全是绿的。

### 1.4 新调查线完全无法进行

`exploration.js` 新增了 `-puzzle` 类型互动物，`Exploration.act(s, id, choice)` 返回 `{text, choices}` 要求 UI 渲染选项。**但 `game.js` 没改**，只渲染 `result.text`。

结果：玩家走到推理点，看到题目，**没有任何按钮可以作答**，八条调查线全部卡死。

### 4.1 本轮新增的技术债（需要记入任务池）

1. **`Exploration.validate` 的允许 id 现在依赖对象数据**：`switches: ids(['switch','puzzle'])`、`opened: [...ids(['chest']), ...regions.map(z=>z+'-task')]`。这意味着**删掉或重命名任何一个互动物，都会让含该 id 的老存档失效**。B-7 那条"校验与配置解耦"现在更紧迫了。
2. **`Interiors.prop()` 有静默丢弃路径**：家具与已授权互动点重叠时 `root.remove(a); return;`，不报错。我实测八个区域的家具都还在（collider 数 ≥ 计划数），但这个静默路径以后很容易让房间变空而没人发现。
3. **室内亮度偏高**：实机截图里室内接近过曝（地面本应是 `#c5d6cd`/`#c2d0e0` 之类的浅色，但看起来接近纯白）。`hemi.intensity=.95 / sun.intensity=1.5` 加上浅色材质。属美术范畴，建议 GPT-6 调。
4. **帧率**：集成前后测得多为 80–132 fps（波动来自系统负载）。`Characters` 每位角色约 50 个 mesh，八处室内全部访问后累计约 1200 个 mesh。目前 `indoor.root.visible=false` 时不会被渲染，暂时安全；但若未来要同屏多个室内，需要做角色网格共享或 LOD。
