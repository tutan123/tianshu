## 2. T-28 · Kenney 色彩空间 bug（本轮最重要的发现）

**在统一树木时撞出来的，但它影响游戏里每一个 Kenney 道具。**

Kenney 的模型把调色板当作 **sRGB 字节**写进了 glTF 的 `baseColorFactor`，而 glTF 规范定义这个字段是**线性**的。`WorldArt.asset` 直接当线性读，于是所有 Kenney 道具都被冲淡：

| 部件 | 应显示 | 实际显示 |
| --- | --- | --- |
| `woodBark`（树干） | `#E28357` 中棕 | `#F2BE9E` 发白的肉色 |
| `leafsGreen`（叶） | `#29C9AB` 饱和青绿 | `#70E6D6` 淡薄荷 |
| `leafsDark`（深叶） | `#2BA6AA` | `#72D3D5` |

**判定依据不是我的推测**：Kenney 官方预览图 `assets/kenney-nature/Side/tree_oak.png` 里树干就是中棕色、叶子就是饱和青绿。我按新公式反算得到 `#E28357`，与官方预览一致。

**这同时解释了体检报告里的 B-10「室内接近过曝」** —— 家具（沙发、桌子、洗衣机）全部发白正是同一个原因。修正后家具恢复了真实饱和度。

改动只有一行（`new THREE.Color().fromArray(part.color)` 后加 `.convertSRGBToLinear()`），已记入 `assets/SOURCES.md`。

## 3. T-14 · 统一树木（B-5）

**问题**：校园网格用程序化二十面体树冠，而 `world-art.js` 给外围用 Kenney 网格 —— 同屏两种风格。

**障碍**：当时只转换过 2 种树（`tree_oak` / `tree_detailed_fall`），把 100 多棵树换成 2 种外形只是换一种难看。

**做法**：`docs/export-kenney.py` 依赖 Blender，我写了 **`docs/export-kenney.cjs`（纯 Node）** 替代它，模型从 23 个扩到 **38 个**（12 种树 + 灌木/草/花/岩石/木堆）。

**关键：转换器是被验证过的，不是被信任的。** `node docs/export-kenney.cjs --verify` 会重新推导已提交的 23 个模型并逐顶点比对，当前报告 `all 23 committed models reproduced exactly`。这个校验抓出了我两处实现错误：

1. 必须遍历 **场景图**，否则嵌套家具（bedBunk/desk/chairDesk）会丢掉父节点变换；
2. Python 的颜色分组是**每个对象重置一次**（`groups = {}` 在对象循环内），不是全局合并；同名颜色会产出多个 part。

## 4. T-15 · 遮挡淡化（B-3）

两个独立缺陷叠在一起，才让它变成一整块糊屏的脏板：

1. **只用 AABB 判定**。那个包围盒比墙体外扩、还含屋顶高度，所以相机→玩家的射线会擦到盒子，而玩家其实清清楚楚看得见 —— 白白淡化。现在 AABB 只做粗筛，再用真实网格射线确认，并且**采样脚/躯干/头三点，全部被挡才淡化**。
2. **`depthWrite=false`**。建筑的前面、后面、内部细节全部互相叠加混合，糊成一团。现在恢复写深度、不透明度 0.3，读起来是一块完整的半透明体积，玩家以 70% 透出。

另外把重算频率降到每 3 帧一次（遮挡变化慢，射线不便宜）。

**验证**：`architecture.acceptance.js` 里有一条刻意写的断言「站在图书馆前，前景实验楼必须淡化」—— 更严格的规则仍然通过，说明没有把该淡化的场景漏掉。

**仍然存在的限制**（如实说明）：当相机正对建筑背面时，那块半透明面依然占屏较大。要让玩家在画面里看到建筑**内部**（而非整体淡化），需要按网格裁一个"窗口"，或改成相机自动拉近。这是交互/aesthetic 决定，留给 GPT-6 或用户。

## 5. T-17 · 室内标签（B-10 前半）

`label()` 原来在文字后面铺一整条 512×80 的不透明 `#172a32` 底板 —— 在俯视室内镜头下，这些黑条是画面里最响的元素。现在换成贴合文字宽度的半透明圆角底 + 深色投影。

## 6. 存档 id 耦合（第 0 阶段遗留的技术债）

`Exploration.validate` 原来从**当前对象列表**推导允许的 id，所以删除或重命名任何互动物，都会让含该 id 的老存档变成"损坏存档"。

现在改为 **`HISTORICAL_IDS` 冻结快照 ∪ 当前对象列表**。已实测：在沙箱里把 `dorm-npc` 改名后，含旧 id 的存档**仍然可以恢复**。新增两条单测保证快照完整、且凭空捏造的 id 仍被拒绝。
