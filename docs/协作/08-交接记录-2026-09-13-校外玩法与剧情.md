## 1. 校外玩法与剧情做了什么

### 1.1 七条现场调查线

七栋校外建筑各一条，沿用校史馆那套**已经被 97 项验收覆盖**的机制：与当地人交谈 → 找到线索 → 现场推理 → 结案领赏。

每条都长在 GPT-6 自己写好的钩子上，而不是另起一套故事：

| 建筑 | 调查线 | 来自 GPT-6 原有的台词 |
| --- | --- | --- |
| 南门旧书局 | 底片上的钟楼 | 「底片上的钟楼还没建成」 |
| 雨巷咖啡馆 | 每周三的空位 | 「每天为同一个缺席的客人留一张靠窗桌」 |
| 榕树便利店 | 雨天的胶卷 | 「雨天总有人来问一卷过期胶卷」 |
| 像素游戏厅 | 没人操作的机台 | 「旧街机仍在运行」 |
| 青禾社区诊所 | 写在明天的名字 | 「值班登记里，你的名字被写在明天」 |
| 回声照相馆 | 另一种校园布局 | 「冲印机里留着校园的另一种布局」 |
| 砚池校史馆 | 同一天的三次改写 | 「同一页校刊被改写过三次，墨迹却都来自同一天」 |

**刻意不新增室内可互动物。** 这些都挂在 `CampusRooms` 已经生成、并且已被 `expansion.acceptance.js` 逐层证明可达的 `-f1-npc` 与 `-f1-note` 上 —— 内容层不再引入一次寻路风险。

七道题的**正确答案位置是打散的**（1/2/2/1/0/2/0）。全放同一个位置，玩家第三次就会停止读题。

### 1.2 故事链「荷池底片」

三段调查串成一条线，按顺序解锁，终章在沿河步道：

```
旧书局结案 → 交底片 ─┐
                     ├→ 照相馆结案 → 交样张（需先持底片）
                     ├→ 校史馆结案 → 交原件编号（需先持样张）
                     └→ 沿河步道显影台 → 「未显影底片」（唯一装备）
```

门控是真的：照相馆在自己案子结清、但玩家还没拿到书局底片时**不会**交样张；显影台在三件物证不齐时拒绝工作。

唯一奖励「未显影底片」是**第一件不出现在任何商店 wares 里的装备**。能安全地新增装备，是因为之前把存档校验的边界改成从装备表推导（T-08）—— 这是那次修复的回报。

### 1.3 集成方式：五处小钩子

没有重写 GPT-6 的模块，只在需要的地方各加一行：

| 位置 | 改动 |
| --- | --- |
| `index.html` | 在 `exploration.js` 之后加载 `offcampus.js` |
| `campus3d.worldObjects()` | 室内追加 `OffCampus.objects(zone,floor)`，室外追加 `OffCampus.outdoor()` |
| `campus3d.enterInterior()` | 为新物件补 `WorldArt.interactables` 视觉 |
| `exploration.js all()` / `allowedIds()` | 合并内容层的物件与稳定 id 清单 |
| `exploration.js quests()` | 合并校外任务条目 |
| `game.js worldInteract()` | 先问 `OffCampus.act`，返回 `undefined` 才交给 `Exploration.act` |

`world-art.js` 的 `outdoor()` 也补了一处，让扩展区的户外物件有实体。

存档兼容：校外 case id、故事链 flag、终章 id 全部进 `OffCampus.historical`，`TS.restore` 对「七案全结 + 三物证 + 终章」的存档往返通过。

中途踩到两个坑，都是测试自身的问题，值得记下来：

1. **又是 `pagehide` 自动存档。** 我先用 `page.evaluate` 直接改 `localStorage` 再 reload，被即将卸载的页面写回覆盖 —— 因为它只改了存档、没改游戏内存里的 `state`。改成**全程走 UI** 后反而更有说服力。
2. `worldObjects()` 只返回**当前区域**的物件。我在咖啡馆里断言七栋楼的对象，自然全都找不到。
