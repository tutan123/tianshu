### B-1 【高】验证闭环断裂 —— 这是我最该先修的东西

这一条不是"代码有 bug"，而是**整个协作模式的地基**：GPT-6 每轮改完只能靠"我看截图觉得对"验收；你说"GPT-6 额度用完我就用你" —— 而我接手时如果没有任何机器可验证的手段，我的改动就是**无凭据的改动**，风险比不改还高。最终结果是两个人轮流往一个 2404 文件 / 44.5 MB 的仓库里塞东西，没人能证明它还是好的。

**证据 1：依赖缺失**

```
node -e "require.resolve('playwright')"  →  MODULE_NOT_FOUND
```

`README.md:49` 与 `docs/建筑美术参考与素材边界.md:48-55` 都把浏览器验收当作质量门禁，但这些脚本**现在一条都跑不起来**（`run-browser.cjs:4` 直接 `require('playwright')`）。`tests/*-results.json` 里躺着的通过记录是**历史结果**，不代表当前状态。

**证据 2：即使装上依赖，也有一套永远跑不起来**

`tests/browser.acceptance.mjs` 用的是 **ES Module**（`import { writeFile } from 'node:fs/promises'` + `export default async function`），
而 `tests/run-browser.cjs:12` 是用 `vm.runInThisContext('(' + source + ')')` 去包一层括号加载的 —— 那只适用于 `async (page) => {...}` 这种表达式形式。

我补了一个 `playwright` → `playwright-core` 的垫片后实测：

```

tests/browser.acceptance.mjs:1
(import { writeFile } from 'node:fs/promises';
 ^^^^^^
SyntaxError: Cannot use import statement outside a module
    at Object.runInThisContext (node:vm:317:16)
```

**也就是说：原首章那 54 项验收（`browser-results-v3.1.json`）现在没有任何入口可以重跑。**

**证据 3：好消息 —— 其余 4 套是真能跑的**

同样补上垫片后，我实跑了最新的一套：

**39 项建筑验收全部通过，零错误。** 完整结果留档在 `证据/baseline-architecture-results-2026-09-13.json`。
（跑完我把 `tests/architecture-results.json` 按原字节还原了，文件哈希前后一致 —— 仓库零改动。）

**结论**：`exploration.acceptance.js`、`arcade.acceptance.js`、`outdoor.acceptance.js`、`architecture.acceptance.js` 这 4 套（都是 `async (page) =>` 形式）是好的，只缺依赖；
只有 `browser.acceptance.mjs` 需要修运行器。

**建议做法（第 0 步，0 风险，不动游戏逻辑）**

3. 加 `verify.cmd`：4 套单测 → 5 套浏览器验收 → 汇总 + 截图。

### B-2 【高】实验楼失手会永久锁死一个结局（真实软锁）

这是一个**跨 3 个文件、现有测试没覆盖到**的逻辑缺陷。追踪链路：

```
content.js:44    lab 成功 → flags: ['evidence']
                 lab 失败 → flags: ['receipt']      ← 失败分支
content.js:59    nodes.hearing.choices[0].needFlag = 'evidence'
state.js:24      dawn（破晓之人）结局要求：flags 含 'evidence' 且含 'public'
```

**推导**

1. `evidence` 这个 flag **全仓库只有一个产生点**：`content.js:44` 的 `lab` 节点成功奖励。
2. `lab` 是主线节点，`repeatable` 未设置 → **不可重玩**。电路小游戏失败一次，本局就再也拿不到 `evidence`。
3. `hearing` 答辩节点的选项 0（"公开修改记录"）被 `needFlag='evidence'` 锁死 → 本局**永远呈现为灰色不可点**。
4. 而"破晓之人"结局硬性要求 `evidence && public` → **本局永远拿不到第 3 个结局**。

**并且**：失败分支给的 `receipt` flag，我用 grep 全文搜索过 —— **没有任何代码读它**。它是一个悬空的死 flag。

**影响**：这直接违反了 `docs/探索版设计与迭代记录.md:86` 自己写的原则
「剧情失败仍推进故事，不把互动影游变成强制刷数值的关卡游戏」。
玩家在一个小游戏里手滑一次，就永久失去一条叙事路线，而且界面上只表现为一个灰按钮，没有任何解释。

**现有测试为什么没抓到**：`state.test.cjs` 的
`choices set persistent route flags and all three endings are reachable`
只走成功分支来断言三个结局可达，没有覆盖"lab 失败"这条路径。

**建议修法（二选一，我倾向 A）**

- **A（最小改动）**：`lab` 失败时也授予 `evidence`，只降低数值奖励；`receipt` 改为影响 `hearing` 选项 0 的**说服力文案**而不是可用性。理由：失败仍推进故事，符合既定设计原则。
- **B（保留代价感）**：让 `receipt` 成为选项 0 的**替代前置**，即 `needFlag` 改为"有 evidence 或 receipt"，但失败路线的声望收益降低（例如 +10 而非 +25）。

无论哪种，都应该**同时补一条单测**：断言"lab 失败后三个结局依然可达"。

### B-3 【中】遮挡淡化视觉崩坏

**证据**：见 `证据/05-walk-night.webp`。画面下半部分被一大块半透明灰绿板占据，能透过它看到零散几何体，观感像渲染故障而不是"前景建筑淡化"。

**代码**：`campus3d.js:38-45`

```js
function applyOcclusion(enabled) {
  for(const item of architectureVisuals)for(const part of item.meshes){
    if(enabled&&item.faded){
      if(!part.ghost){part.ghost=part.original.clone();
        part.ghost.transparent=true;part.ghost.opacity=.14;
        part.ghost.depthWrite=false;}   // ← 关闭深度写入
      part.object.material=part.ghost;
    }else part.object.material=part.original;
  }
}
```

三个叠加问题：

1. `depthWrite=false` + 整栋楼所有面都半透明 → 前后表面互相叠加，变成一团糊。缺少"只保留轮廓"的视觉线索。
2. `opacity=.14` 对一栋 13×7×6 的建筑来说太淡，等于给整个屏幕盖了一层灰膜。
3. `campus3d.js:275-277` 每帧调用 `applyOcclusion(true)` / `applyOcclusion(false)`，对 11 栋 × 每栋 11~15 个对象**逐帧重写 material 引用**。视觉差 + 白白浪费。

**GPT-6 更适合做这个**：它需要的是审美反复（尝试轮廓描边 / 只淡最近一面墙 / 提高透明度但保持深度 / 改成"屋顶消失"剖面法），这是它的强项。

### B-4 【中】战斗几乎不可能输（实测确认）

我没有手算下结论，而是**用探针真的打了一遍**。脚本注入一份合法中期存档 → 通过真实 UI 点进 `duel` → 采用最笨的策略（每回合把所有行动力都打"破绽突进"，然后结束回合，**全程不格挡、不读招**）。

**实测结果**（原始数据见 `证据/combat-report.json`）：

| 回合 | 我方 HP | 敌方 HP | 说明 |
| --- | --- | --- | --- |
| 开始 | 75 | 85 | |
| 1 结束 | 63 | 52 | 三拳 33 伤害，挨 12 |
| 2 结束 | 44 | 19 | 三拳 33 伤害，挨 19 |
| 3 | 胜 | 0 | 结局 `success` |

**结果：3 回合通关，总共只掉了 31 / 75 血，一次防御都没用。**
"稳住护架"和"因果读招"两张牌在最优解里是**无用的**。战斗作为叙事高潮（"未被演算的那一拳"）没有产生任何张力。

顺带确认了一件好事：**手工构造的中期存档被 `TS.restore` 正确接受**（进度 08/10，主线标题"未被演算的那一拳"，主线链推进到 `duel` 完成）—— 存档系统是可靠的。

**建议**：这不是"改大数字"能解决的。真正的问题是**没有失败压力**。可选方向：
- 敌方伤害改为递增曲线，或用"回合上限"制造紧迫感；
- 让"读招"成为必需而非可选（不读招就吃满伤害）；
- 引入算力作为战斗资源（现在是 10 算力买 1 行动力，但根本不需要买）。
数值调整建议放到 B-7 修完之后做，因为现在改数值会牵动存档校验。

### B-7 【中】存档校验阈值硬编码 —— 一颗定时炸弹

**代码**

- `state.js:63-66`：`validEncounter` 把 `remaining ≤ 60`、`energy ≤ 5`、`maxEnemy === 85`、`hp ≤ 1000000` 等全部写死。
- `salvage.js:19`：`valid()` 同样把 `remaining ≤ 60`、`length ≤ 490`、`score ≤ 2000` 写死。

**为什么危险**

`RPG.items.pendant`（`rpg.js:8`）给 `time: +6`，而 `salvage` 初始 `remaining = 45 + bonus.time`（`salvage.js:13`）= **51，距离上限 60 只剩 9 秒余量**。

也就是说：**只要 GPT-6 后续加一件 `time: +10` 的装备或消耗品，所有玩家已有的回收存档会瞬间变成"损坏存档"被 `TS.restore` 拒绝**，表现为"存档无法读取"。而且这种故障极难定位——玩家会以为是浏览器问题。

**建议**：把数值上限从校验函数里抽出来，改为由配置推导，例如
`const maxRemaining = 45 + 最高可用 time 加成 + 余量`，或在 `RPG.bonus` 上暴露 `maxTimeBonus()` 供校验引用。

**这条应该在做任何数值/装备迭代之前先修。** 属于我。

### B-15 【低】剧情中每 2 秒全量写 localStorage

## 四、关于"要不要升级 Three.js"

结论：**短期不要动。**

- `vendor/three.min.js` 是 **r149**（2023-01），且用的是 **UMD 全局构建**。
- Three.js 从 r150 之后**不再发布 UMD 版本的 `three.min.js`**，只有 ESM。
- 而这个项目**必须**用 `file://` 直接打开（`开始游戏.cmd`、README 都强调"纯静态离线页面，不需要启动服务器"），**ES Module 在 `file://` 协议下会被浏览器的 CORS 策略拦截**。

所以升级 Three.js 等于要求引入构建步骤或本地服务器，会破坏"双击即玩"这个对 Demo 极其重要的特性。

代码里用的 `ColorManagement.legacyMode`（`campus3d.js:123`）、`outputEncoding`、`sRGBEncoding` 都是 **r149 正确的 API**，并不是写错。真正需要知道的是：**这个版本是被 `file://` 约束锁定的，不是"忘了升级"**。

我把这条写进 [`03-项目速览-给下一个Agent.md`](03-项目速览-给下一个Agent.md) 的「不要动的东西」里，就是为了防止下一个 Agent（无论是我还是 GPT-6）出于"技术债"直觉去做这个升级，然后发现要引构建系统，最后把整个离线特性搞坏。
