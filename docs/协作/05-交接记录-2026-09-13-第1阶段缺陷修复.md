## 2. T-07 · 实验楼软锁（B-2）—— 本轮最重要的一条

**问题**：`evidence` 这个 flag 全仓库只有一个产生点（`content.js` 的 `lab` 成功奖励），而 `lab` 不可重玩。所以电路小游戏失手一次，就永久失去「破晓之人」结局，而且答辩界面会留下一个永远点不动的灰按钮。

**修法**（三处，缺一不可 —— 我漏了第三处，被自己写的测试抓住）：

1. `state.js` 新增 `choiceState(s, id, index)`，支持 `needFlagAny`（任一即可），并返回 `{selectable, locked, poor}`。
   渲染层和判定层现在调用同一个函数，按钮状态和规则不可能再不一致。
2. `content.js`：`hearing.choices[0]` 从 `needFlag = 'evidence'` 改为 `needFlagAny = ['evidence', 'receipt']`，并加 `lockedHint`。
3. `state.js` 的 `ending()`：原来硬要求 `evidence && public`，改为 **`public` + （`evidence` 或 `receipt`）**。
   两条路线结局 id 相同（仍是 3 个结局），但文本不同 —— 只有回执时坦白「不足以指认是谁动的手，但足以让评审重新表决」。
4. `game.js`：选项渲染改用 `TS.choiceState`，锁定时显示 `c.lockedHint`。

**验证**

- 新增单测 `failing the lab puzzle still leaves every ending reachable`：走完主线但让 `lab` 失败，断言 `receipt` 被授予、答辩选项 0 可选、最终结局是 `dawn`；同时断言完整证据路线仍然可用，且两条记录都没有时仍然锁定。
- 真实 UI 实测（`hearing.cjs`）：

| 存档 flag | 答辩选项 0 | 提示文案 |
| --- | --- | --- |
| 只有 `receipt` | **可点** | 需要完整证据或申请回执 · 声望 +25 |
| 只有 `evidence` | 可点 | 同上 |
| 两者都无 | **禁用** | 缺少可以提交的记录 |

## 3. T-08 · 存档校验与配置解耦（B-7）

**问题**：`state.js` 与 `salvage.js` 把数值上限硬编码在存档校验里。回收小游戏的 `remaining ≤ 60`，而初始值是 `45 + 吊坠6 = 51`，只剩 9 秒余量 —— 只要加一件 `time: +10` 的装备，所有玩家在回收中途的存档都会被判为「损坏」。

**修法**：

| 位置 | 改动 |
| --- | --- |
| `rpg.js` | 新增 `limits()`：按槽位取最大值再求和，从装备表推导出攻击/格挡/生命/时间/窗口/回收速度/回收价值的**合法上限** |
| `minigames.js` | 抽出 `QUIZ_BASE_SECONDS` / `QTE_SECONDS` / `COMBAT_*` 常量与 `quizSecondsFor()`；导出 `MiniGames.limits` |
| `salvage.js` | 抽出 `BASE_SECONDS` / `OUT_LENGTH` / `MIN_LENGTH` 等常量；`valid()` 与 `step()`、`create()` 共用同一批常量 |
| `state.js` | `validEncounter` 通过 `MiniGames.limits` 取上限；`maxEnemy` 同时接受当前值与历史值 85，保证老存档能读 |

**验证**（实测，不是推断）：

| 场景 | 结果 |
| --- | --- |
| 现有老存档（51 秒，无新装备） | 通过 |
| 假设以后加一件 +30 秒配件：合法满配存档（75 秒） | **通过**（改动前会被拒绝） |
| 同一批老存档在新装备表下 | 通过 |
| 调查任务存档（`opened` 含 `-task`、`switches` 含 `-puzzle`）往返 | 通过 |
| 篡改未知 id | 仍然正确拒绝 |
| 不可能的数值（999 秒） | 仍然正确拒绝 |

新增单测 `salvage save bounds follow the item table instead of frozen literals` 把这个行为固化下来。

## 4. T-13 · 战斗数值（B-4）

**先测量，再调参。** 我用真实模块跑出「正常剧情路径到达决斗时」的实际状态：

```
到达决斗前: level = 3  xp = 260  加成 = {attack:2, hp:8}
maxHp = 91   physique = 36
每拳 13 伤害 → 每回合 39   |   每次格挡 12
```

原参数下敌方 85 HP，玩家 3 回合打完、只掉 31 血，**全程不格挡必胜**，两张防御牌是最优解里的废牌。

**改动**（`minigames.js`）：

- 敌方 HP `85 → 120`
- 伤害不再是固定的 12/19/10/23，而是 `招式伤害 + 10 + 12 × (回合-1)`
  → 22 / 41 / 44 / 67 / …

**实测四种打法**（真实 UI，同一份 Lv.3 存档）：

| 打法 | 结果 | 过程 |
| --- | --- | --- |
| 全攻不防（naive） | **失败** ✓ | R1 91→69，R2 →28，R3 被 44 伤害击杀（累计 107 > 91） |
| 读招 + 超频（验收套件打法） | **成功** ✓ | R1 74hp/73enemy，R2 33/34，R3 击杀 |
| 两次格挡（规划打法） | **成功** ✓ | R4 击杀，剩 8 血 |
| 纯格挡 | **失败** ✓ | R6 被击杀（打不动） |

现在：**不防御必败，用读招/格挡/超频才能赢**。原本在最优解里毫无用处的两张防御牌变成了通关必需。
`browser.acceptance.mjs` 的打法（读招 + 超频 + 全攻）仍然胜利，所以验收不受影响。

## 7. 本轮新增的技术债

1. **`Exploration.validate` 的允许 id 依赖对象数据本身**（`switches: ids(['switch','puzzle'])`）。
   这意味着**删除或重命名任何互动物都会让含该 id 的老存档失效**。我这次只把数值上限解耦了，id 层面的耦合还在。建议下一轮把 id 列表快照成一份显式清单。
2. **`Interiors.prop()` 有静默丢弃路径**（家具与授权互动点重叠时直接 `root.remove` 且不报错）。本轮实测八区家具都在，但这个路径以后很容易让房间变空而无人发现。
3. **战斗数值仍然依赖玩家等级**。本轮按 Lv.3 调参；Lv.5 以上或买了装备的玩家会明显更轻松。这是刻意的（成长应该有回报），但如果以后加装备，需要重新跑一次 `balance.cjs`。
   该脚本的逻辑保留在本文件第 4 节，需要时可复现（四种打法的卡序：`[s,s,s]` / `[assist,read,s,s,s]` / `[s,s,s],[g,s,s],[g,s,s],[s,s,s]` / `[g,g,g]`）。
