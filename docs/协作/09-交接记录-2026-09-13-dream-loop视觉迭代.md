## 1. 方法

用 [dream-loop](https://github.com/achimala/dream-loop) 的闭环：**先有目标图，再照它改，每轮重拍同一批机位对比。**

关键做法是**机位固定**：`.dream-loop/capture.cjs` 用同一套 `setMode/zoom/weather/enterInterior` 拍 9 个机位（总览、图书馆前、钟楼庭院、镜湖、宿舍室内、校史馆三层、南门商店街、夜景、移动端），每个机位存带 HUD 和纯 3D 两个版本。**这样两轮之间的差异只可能来自代码，不会来自相机角度。**

第一轮之前先拍了一套基线（`baseline/`），作为生成目标图的输入 —— dream-loop 要求目标图是"在现有画面上改进"，不是重新想象一个场景。这一条做到了：用户给的目标图与 `02-walk-library` 是同一个机位、同一个构图。

**贴图用确定性伪随机（LCG，按名字播种）**，不用 `Math.random`。否则每轮贴图噪声都不同，逐轮对比会被噪声淹没。

## 4. 还没达到目标图的地方（下一轮的候选）

按差距排序：

1. **广场偏空** —— 目标图里建筑基座有花池、草地有零星草花、铺装有收边与色带；现在广场是大片均匀铺装，缺少这些小尺度层次。这是目前最明显的一处。
2. **花池与地被** —— 目标图窗下有花箱、草坪有花点。游戏里 `flower_redA`/`flower_yellowC`/`grass_large` 都有，只是校园核心区没铺。
3. **立面仍偏亮** —— 窗框对比出来了，但墙面比目标图浅，缺暖色调的石材分块感。注意：建筑用共享 `BoxGeometry` + 矩阵合批，UV 恒为每面 0..1，**做不了按世界坐标平铺的石材分块**，除非改合批方式或上三平面着色。
4. **遮挡淡化虽然能透光，仍是一块大面积浅色**。目标图里它的结构更清楚。彻底解决要按网格裁窗口或让相机自动拉近。
5. **树种形态** —— 颜色对了，但形态仍以圆锥/球体为主，目标图里有更细腻的层次。

## 5. 给下一个 Agent 的提醒

- **改任何贴图前先读 `campus-buildings.js` 的 `rng()`**：贴图必须逐轮一致，用 `Math.random` 会让 dream-loop 的对比失效。
- `campus3d.js` 的 `box()` 用 `worldUv` 这个 Map 决定哪些材质按世界坐标取 UV。新增带贴图的地面材质要往里面注册密度，否则贴图会被拉伸到整块地面。
- 建筑立面的贴图受合批限制（每个面 UV 0..1），不要试图在上面做规则石材分块。
- 重拍基线：`node .dream-loop/capture.cjs [输出目录]`。
- **`.dream-loop/` 是 gitignore 的**：目标图、基线、各轮截图都不入库。要给别人看效果，得单独导出。
