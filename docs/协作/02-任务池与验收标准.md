## 二、验收标准（Definition of Done）

一个任务只有**同时**满足以下条件才算完成。

### 通用

- [ ] `verify.cmd` 全绿（或明确说明哪些既有失败与本次无关）
- [ ] 没有新增 `pageerror` / `console.error`
- [ ] 没有新增外部 http(s) 请求（必须保持离线自足）
- [ ] 桌面 1440×960 与移动 390×844 均无水平溢出
- [ ] `tests/*-results.json` 已更新且是 re-run 出来的，不是手改的
- [ ] 已 `git commit`，commit message 写清"改了什么 / 为什么"

### 涉及存档数据的任务（T-06 / T-07 / T-12 等）

- [ ] 用**旧版本**（改动前的）存档导入后仍能正常恢复
- [ ] 篡改/损坏存档仍被正确拒绝
- [ ] 新增 flag / 字段有明确消费者，不留悬空 flag（B-2 的教训）
- [ ] `docs/探索版设计与迭代记录.md` 的架构段同步更新

### 涉及美术/视觉的任务（GPT-6 主场）

- [ ] 至少 4 张截图：白天步行 / 夜景 / 室内 / 移动端
- [ ] 截图里能明确看出"改前 vs 改后"的差异，不是同一张换个角度
- [ ] 桌面步行帧率不低于 **60 fps**（当前基线 116）
- [ ] 8 处室外入口 + 8 处室内寻路仍然全通（美术改动很容易撞坏碰撞体）

### 涉及数值的任务

- [ ] 给出**实测**的通过/失败回合数，不是"应该差不多"
- [ ] 说明在最优策略和最笨策略下分别的结果
- [ ] 新旧手感对比写进验收记录

## 五、风险登记

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 两边同时改同一文件 | 互相覆盖，返工 | 硬性约定：一个时间只允许一个 Agent 写；写完必 commit |
| 改数值把老存档弄坏（B-7） | 玩家存档"无法读取" | T-08 先做，任何数值迭代之前 |
| 美术改动撞坏碰撞体 | 玩家卡住 / 进不去门 | 验收标准强制跑 8+8 寻路全通 |
| 占位视频授权（B-9） | 公开发行受阻 | T-23 台账；发行前逐项替换 |
| 未提交成果丢失 | v3.1 建筑精修白做 | T-05 立刻提交 |
| 新 Agent 试图"现代化"技术栈 | 破坏 `file://` 离线特性 | 速览文档「不要动的东西」+ N-01/N-02 |
